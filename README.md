# Containment ⚛️

A JezzBall-style arcade game. Particles are loose in the chamber: build walls to
seal them in, claim 75% of the field, and don't let anything touch a wall before
it's finished.

**[Play it →](https://rvenning.github.io/containment/)**

## How it plays

The rules are JezzBall's, kept on purpose:

- Tap an empty cell to start a wall. It grows **both ways at once**, as a red half
  and a blue half, until each reaches something solid.
- Any region left without a particle in it is sealed and counts as claimed.
  Claim **75%** to clear the level.
- A particle touching a half **while it is still growing** destroys that half and
  costs a life. The other half carries on.
- One wall at a time. Run out of lives or time and the run is over.
- **Level n has n+1 particles and n+1 lives.** There is no level map — it is one
  continuous run, as deep as you can go.

## Features

- **Touch controls built for a phone.** Tap to build in the orientation the
  switch is set to, or swipe across / up–down to build that way from where the
  swipe started. Nothing commits until you lift, and a preview shows exactly
  where the wall will run.
- **Mouse and keyboard**, the original way: left click builds, right click (or
  Space) turns the wall, P pauses.
- **Scoring you can say out loud.** Every claimed cell is worth the level number.
  Clearing a level pays, again times the level, 100 per life left, 5 per second
  left, and 60 for every percent claimed past 75 — so the bold last cut pays.
- **Family leaderboard** of best run score and deepest level, with profiles,
  PINs and cross-device sync.
- Plays offline as an installed app.

## Built on gamekit

Profiles, PINs, storage + Firestore family sync, the sound engine, screens,
canvas effects and PWA install all come from
[gamekit](https://github.com/rvenning/gamekit), vendored into `lib/`.

Re-vendor after a gamekit change:

```bash
node ../gamekit/tools/sync-to-game.js "../containment"
```

Never edit `lib/` directly — the next sync overwrites it. Bump `CACHE` in `sw.js`
whenever any shell file changes, or installed devices keep serving the old build.

## Layout

| Path | What it is |
|---|---|
| `js/rng.js` | Seeded randomness. The engine never calls `Math.random`. |
| `js/sim.js` | One level as a pure simulation: particles, walls, breaches, claiming, the bonus. No DOM. |
| `js/game.js` | The run: level after level, the banked score, the result. No DOM. |
| `js/storage.js` | gamekit storage and the cross-device merge. |
| `js/audio.js` | Synthesized sound effects. |
| `js/render.js` | Canvas, input (tap / swipe / mouse) and the frame loop. |
| `js/main.js` | Screens and the app shell. |

## Local development

```bash
npx http-server . -p 8128 -c-1
```

Then open http://localhost:8128. There is no build step — plain `<script>` tags.

Tests (Node's built-in runner, no framework):

```bash
node --test
```

`tests/sim.test.js` covers each rule on hand-built fields plus a long careless
run checking no particle ever ends up inside a wall; `tests/storage.test.js`
covers the merge; `tests/bot.test.js` plays around sixty whole runs with a cast
of bots (perfect, sharp, ordinary, sloppy, random) that differ in how accurately
they judge where each particle is, and asserts the game separates them.
`node tests/diag.js` prints the balance table.

## Storage

- localStorage prefix `ctm_`
- Firestore collection `containment` in the shared `wordvoyage-e5a5c` project

The Firebase API key in `js/firebase-config.js` is a public client config, not a
secret — it is restricted to the Cloud Firestore API and the rules require an
anonymous sign-in.
